# Hexu 交付与验收

Hexu 起始基线｜2026-10-01｜只规定交接、验收和未定项；业务定义引用 [业务规则](product.md)，取舍依据引用 [来源与取舍](source-notes.md)。

## 接手与交付

| 关口 | 应提交的材料 |
| --- | --- |
| 实施前 | 以 source-notes.md 的起步范围和本表验收项推进；超出已批准业务方向的变更另行确认。 |
| 小范围验证 | 选择公司内一个纯软任务和一个真实软硬件任务；记录真实用户操作与结果，不仅提供模拟结果或截图。 |
| 切换前 | 清点旧项目、任务、对话、附件与未完成工作；说明保留位置、切换及退回办法，不让两套系统重复执行同一任务。 |

用户已批准在独立的 Hexu 目录启动开发；本轮不包含旧环境清理、真实数据迁移、公开发布或生产部署。交接时不得把旧资料或私人记录默认视为可删除、可迁移内容。

## 首轮范围建议

先验证研发任务及直接相关的需求整理、技术分析、测试报告等办公工作。多人和多任务规模由真实使用决定；人格、市场、通用插件安装、广泛办公系统接入和大规模并发不作为首轮前提，也不因此永久排除。

## 验收清单

全部为待验证场景。B 编号指向 product.md 的规则；既有编号保持不变，A23–A26 为 2026-10-05 专家团队能力补充。实际证据级别见 ci/acceptance-coverage.json，不因文档收录而视为实现。

| 编号 | 规则 | 检查场景及应得到的证据 |
| --- | --- | --- |
| A01 | B01、B06 | 未自行配置 AI 的普通成员登录，完成一个有用任务；记录是否需要维护者代操作。 |
| A02 | B02、B06 | 在待开发任务持续多轮讨论，核对 Pi 使用需求梳理技能及其澄清结果；即使出现“帮我实现”等评论，未转待执行前也无开发作业或代码改动，离开再打开仍能继续聊。 |
| A03 | B03 | 负责人形成粗计划并拆分子任务，能查到分工与依赖；未确认的子任务不因拆分动作自动执行。 |
| A04 | B03、B08 | 第二名成员凭任务讨论、已有产物和未解决事项接手，验证后续结果确实使用了这些背景。 |
| A05 | B03 | 用项目内非创建者及原先只能浏览的成员账号互看各阶段任务并评论；非成员、已移除成员及无项目身份的管理员不得访问。 |
| A06 | B08 | 同一专家方法用于两个项目，检查是否仅复用方法而未带出另一个项目的内容或凭据。 |
| A07 | B05 | 在已开始的共享主机作业中关闭浏览器，再打开核对进度、成果和费用。 |
| A08 | B04 | 在工程师真实专用电脑发起任务，核对原代码位置、IDE 与硬件调试方式仍可用。 |
| A09 | B04 | 保留一份人工未提交修改并制造同时编辑场景，验证没有覆盖或静默混入。 |
| A10 | B05 | 让执行环境离线再恢复，检查状态真实、已有操作不重复、任务未擅自换机。 |
| A11 | B05 | 任务遇到必须现场处理的步骤，检查等待提示、责任人处理记录及未验证事项。 |
| A12 | B05 | 取消运行中的任务，核对实际停止情况；不能立即停止时，页面与后续费用记录如实反映。 |
| A13 | B06、B07 | 用简单低风险和困难高风险样本检查后台选择、结果与费用，并核对讨论消耗未遗漏。 |
| A14 | B07 | 检查预算不足、失败重试、重复回报和费用缺失，核对限制、去重及未知费用标记。 |
| A15 | B02、B08 | 交付后先看到简要总结，再能找到成果和验证依据；缺信息、阻塞和返工可被负责人定位。 |
| A16 | B09 | 有验收权者评论明确接受后记录完成；无验收权者同样评论、引用“已完成”或说“还没完成”，不得误验收。 |
| A17 | B08 | 把一次真实返工原因整理成获确认的方法改进，用后续任务验证效果并保留原依据。 |
| A18 | B10 | 替换一种模型、专家方法或环境后，复验已有登录、权限、评论、历史、费用与验收流程。 |
| A19 | B02、B06 | 平台 Pi 可用、目标开发主机未接入或离线时，在 Web 项目内新建待开发任务并讨论；不能被迫先启动目标开发环境。 |
| A20 | B02、B06 | 授权成员将同一任务从讨论转到待执行，核对 Pi 切换至开发技能、沿用已确认结论；条件具备才实际开发，条件不足则等待，不显示开发中。 |
| A21 | B09 | 在待验收评论补充不成熟想法，回讨论；明确修改范围并确认后再进入待执行。两轮讨论和交付都能找回。 |
| A22 | B03、B09 | 多名成员在开发中评论或在已完成任务继续评论，记录均可见；不能自动引起重复开发、未确认的范围改变或任务重启。 |
| A23 | B01、B11 | 不会编排工作流的成员仅说明目标并回应必要问题，平台推荐团队方法、安排角色并汇总结果；记录是否被迫填写流程、命令、模型或逐个管理 Agent，简单任务不强制多专家。 |
| A24 | B02、B06、B09、B11 | 同一任务从多人专家讨论转入开发：确认前无代码或设备改动，确认后沿用讨论结论；内部专家均表示通过时仍停在待验收，人类接受后才完成。 |
| A25 | B03、B07、B08、B11 | 同一团队方法在两个项目复用，核对资料、角色权限与历史不串用；各角色和重试的用量归入对应任务，额度不足及未知费用不被汇总掩盖。 |
| A26 | B04、B05、B11 | 制造专家失败、结论冲突、检查缺失、工作区冲突及整体取消/重启，核对汇总如实标明缺口、所有子工作真实停止或明确未停、恢复不重复执行且不覆盖人工修改。 |


每条记录写明任务与版本、使用者、环境、操作、预期与实际结果、产物及费用依据。结果使用“通过／未通过／未验证／不适用”；不适用需产品负责人确认，未验证不得写成通过。
