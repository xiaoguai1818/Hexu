# 自动测试与验收证据

这里只定义测试层级与证据要求；业务定义只在 [product.md](product.md) 维护，验收清单在 [acceptance.md](acceptance.md)。当前真实产品能力边界见 [status.md](status.md)。

## GitHub 上每次验证的内容

| 层级 | 实际操作 | 不能证明的内容 |
| --- | --- | --- |
| 回归与覆盖率，x64/arm64 | 类型检查、编译、递归发现测试；任务权限、状态、上下文和结果校验；覆盖率门槛为行90%、分支80%、函数90% | 真实模型质量、浏览器操作 |
| 持久化与故障，x64/arm64 | 8个独立进程竞争初始化／版本写入；未提交写入时强制终止；数据库重开、完整性及包含未合并日志的一致性备份恢复 | 跨主机派发与真实任务进程恢复 |
| 编译产物部署，x64/arm64 | 非root精简镜像；导出／载入一致性；隔离网络内两个进程访问真实数据库，通过HTTP检查任务流；强制终止、重建容器、清空测试卷后恢复 | 正式Web产品部署、真实登录、Pi或硬件端到端 |
| 正式 Web 部署与浏览器 | Chromium／Firefox 操作真实登录、项目、成员撤权、任务评论、冲突保留、断网恢复、明确验收与返工、窄屏和键盘；实际进程中断／重建后核对会话与数据 | 真实 Pi 产物、真实主机和完整企业使用验收 |
| 定向变异防回归 | 在临时副本故意破坏8项关键规则，确认原回归测试以断言失败发现问题 | 全程序穷举验证 |
| 安全与测试入口 | actionlint、部署脚本ShellCheck、锁定依赖漏洞审计、敏感路径/常见密钥格式检查 | 完整安全审计或零漏洞保证 |
| 汇总门禁 | 任一必需层失败／跳过／取消均失败；展示全部业务验收缺口 | 工程全绿不代表可上线 |

旧的“编译产物部署”层使用 `ci/fixture-server.mjs`，它只是调用实际编译核心的测试适配层。身份目录及运行回报为明确的测试替身，没有前端页面、真实Pi、真实模型或生产凭据。该文件不进入 `runtime` 产物，只存在于专用 `ci-deployment-fixture` 阶段。不得将其改名为“完整产品E2E”。

Web 层则使用正式 `runtime` 镜像与 `bin/server.mjs`，不含测试 HTTP 后门。预置账号和少量合成交付仅由离线 `test/fixtures/web-seed.mjs` 写入临时卷；测试通过真实表单/API进行变更。仅交付来源为合成样本，认证、授权、数据库、评论、验收操作和浏览器都不是替身。临时凭据不上传；失败轨迹中可能含已销毁的合成账号请求，禁止改用真实账号或业务数据。

## 防止漏测和假通过

测试文件按 `scripts/test-support.mjs` 递归发现，未知目录、空测试集、缺失关键回归文件、禁用／独占测试、跳过或结果数不一致均失败。当前必需文件和最低用例数见 `ci/suites.json`；后续目录必须加入明确的测试层，不能靠文件名过滤无声遗漏。

覆盖报告还须逐项覆盖全部含运行代码的源模块，不能只检查固定的旧文件名单；未被加载的新模块直接使门禁失败。纯类型声明不计作运行代码，但放在接口目录里的实际逻辑仍要检查。禁止用覆盖率忽略指令隐藏缺口。对应自测见 `test/quality/coverage.test.mjs`。

每次保存源码提交、测试清单、TAP、JUnit、覆盖率、变异结果、部署日志及恢复依据。报告不上传临时认证文件。镜像、网络、数据卷仅属于当前CI作业，结束后清理，不修改生产环境。

`ci/acceptance-coverage.json` 只记录验收编号、现有证据位置与未满足条件。GitHub汇总始终展示此表。手动 `Product acceptance readiness` 在缺少真实产品证据时明确失败，而不是跳过。

任务持久化回归同时核对状态与记录是否相互支持：不能接受没有运行记录的开发／待验收状态、没有人类接受记录的已完成状态、重复评论标识或缺少必要时间的完成记录。损坏记录明确报错，不通过重置或补造记录继续工作。

备份回归必须主动构造“最新记录仍在数据库写入日志中”的场景：证明只复制主文件会漏数据，再验证运行产物中的一致性备份能够恢复完整记录；同时检查目标已存在、目标为符号链接、源文件不存在／损坏及并发备份，禁止覆盖已有文件或把不完整结果当作成功备份。

新增 Web 功能必须同步补正式入口的浏览器用例，不能只检查页面字符串。尚未开放的 AI 讨论／转待执行须保持明确不可用且不改变任务；之后实现Pi/Host时，再加入真实Pi接模拟模型服务的协议集成、进程取消、目录保护、断线恢复。使用真实模型和专用硬件的验收只能在批准的测试环境、限额凭据和受审查提交下运行；这些现在均未通过。

## 复现入口

`docker compose run --build --rm check` 复现回归、持久化和测试入口检查。部署检查使用 `HEXU_SOURCE_SHA=<当前提交> HEXU_CI_TAG=<唯一测试标签> bash scripts/deployment-check.sh`，只在专用测试环境运行。`node scripts/readiness.mjs --require-product` 检查上线证据，不执行生产部署。

Web 容器测试入口为 `HEXU_SOURCE_SHA=<提交> HEXU_CI_TAG=<唯一标签> bash scripts/web-check.sh`；默认 Chromium，可用 `HEXU_BROWSER=firefox` 选择另一浏览器。无容器的本机补充验证使用 `scripts/local-web-check.mjs`，安装与运行说明见 [web.md](web.md)。两者复用同一份浏览器用例；本机临时账号、数据库和服务结束后清理，不取代 GitHub 全套门禁。
